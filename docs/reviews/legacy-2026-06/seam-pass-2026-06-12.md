- **KEY FACT (verified):** `node_state.shift_state` is a **MIRROR/projection** of the `shifts`
  table (`services/shift/transition.rs:47` "this mirror updates shift_state ONLY"). The `shifts`
  table is source-of-truth; node_state.shift_state is a denormalised pointer. The node_state.rs
  caller-contract EXPLICITLY warns: do not blindly upsert `shift_state=Closed` over a row that
  may carry `Opened` — "would mask the recovery requirement" (bd-issue PRRO_GATE-ah8).
- **SEAM-D-1 | MED (new, CONFIRMED — composes with the just-merged NC-03).**
  My NC-03 fix (PR#148) branch (a) reconstructs the lost node_state row via
  `upsert_initial_tx(fn, Online, **Closed**, next_lnd)` + `current_shift_id=NULL`, reading ONLY
  `fiscal_documents` (max_lnd, last_ack) — it does **NOT** query the `shifts` table. But NC-03's
  domain (node_state lost, ledger survived) is the SAME DB file, so a surviving **OPEN `shifts`
  row** can coexist. Boot's crashed-shift recovery triggers only on `shift_state==Opened AND
  current_shift_id IS Some` (`boot_phase.rs:2910`); NC-03 set it to `Closed/NULL` → the surviving

  ledger-survived path should query `shifts`; if an open shift exists either preserve
  `shift_state=Opened`+`current_shift_id` so boot recovery sees it, OR (minimal) record the
  open-shift fact in the CRITICAL audit payload + RUNBOOK unblock step. This upgrades my own
  parked NC-03 residual from "noted" to a located, fixable item.
- §16.7 manual-recon routing: the drain reject of an OFFLINE_LOCAL_ACK backlog doc on

## Locked contract — SEAM-B-3 fix (architect → implementer, 2026-06-13)

**Scope:** give the drain's SentReplay lastChk classifier the M1-02 superseded exception that
boot + convergence already have via `dispatch_sent_via_probe`, so a superseded SENT doc reaching
the drain does NOT hard-abort the whole FN drain.

**Where:** `services/offline_sync/kvt2_confirm.rs` — `classify_check_result`, the
`Err(DpsError::ServerFiscalIdMismatch { expected_id, actual_id })` arm (currently routes
UNCONDITIONALLY to `Kvt2ConfirmOutcome::StructuralDrift{ LastChkIdMismatch }` → `BootError::Internal`
halt).

**Contract:**
1. The superseded test mirrors boot's `dispatch_sent_via_probe` TIP_SUPERSEDED arm: a Mismatch is
   "superseded" when the probed doc is NOT the FN's newest submitted doc — i.e. its `lnd` is less
   than `fiscal_documents::max_submitted_lnd(fn)` over the `{SENT,KVT1,KVT2,ACK}` set (reuse the
   EXISTING `max_submitted_lnd` repo fn added in the M1-02 batch; do NOT add a new query).
2. `classify_check_result` is currently a PURE fn (no DB). It must NOT become impure. So thread the
   superseded verdict in as an input: the caller (`confirm_drain_doc` / the SentReplay drain path)
   reads `max_submitted_lnd` + the doc's `lnd` BEFORE calling the classifier and passes a
   `superseded: bool` (or an enum) — classifier stays pure, testable. Mirror how the boot arm
   obtains its superseded flag.
3. On `ServerFiscalIdMismatch` AND `superseded == true`: route to a NON-fatal outcome — a new
   `Kvt2ConfirmOutcome` variant (e.g. `SupersededHold`) that the drain maps to: NO doc-state change
   (doc stays put), `TIP_SUPERSEDED`-class audit (reuse the boot event/label for parity), and the
   drain CONTINUES (does NOT `BootError::Internal`-halt the FN). Mirror the boot arm's
   `complete_probe_trace_tip_superseded` semantics for the trace row if a trace is open in the
   drain path.
4. On `ServerFiscalIdMismatch` AND `superseded == false` (Mismatch on the actual tip): UNCHANGED —
   `StructuralDrift{ LastChkIdMismatch }` (genuine drift on the newest doc IS fatal/escalates).
5. Invariants: no new doc-state transition beyond the ruled no-op hold; no wire/crypto added; pure
   classifier stays pure; minimal diff.

**Pins (mandatory):**
- A drain SentReplay where the probed SENT doc is superseded (a higher-`lnd` submitted doc exists)
  + DPS returns the tip's id → assert the FN drain does NOT halt (`BootError`), the doc is held
  (no state change), a `TIP_SUPERSEDED`-class audit is emitted, and `invariant_scan::assert_clean`.
- A drain SentReplay Mismatch on the ACTUAL newest doc → still `StructuralDrift` (unchanged) — pin
  that the fatal path is preserved for genuine tip drift.
- `classify_check_result` unit tests stay green (the pure fn keeps its existing signature semantics
  for the non-superseded cases).

**Gate:** `cargo nextest run -p prro --features test-support` + fmt + `clippy -D warnings`.
