## SEAM-D — shift ↔ offline-session ↔ node-mode
- **KEY FACT (verified):** `node_state.shift_state` is a **MIRROR/projection** of the `shifts`
  table (`services/shift/transition.rs:47` "this mirror updates shift_state ONLY"). The `shifts`
  table is source-of-truth; node_state.shift_state is a denormalised pointer. The node_state.rs
  caller-contract EXPLICITLY warns: do not blindly upsert `shift_state=Closed` over a row that
  may carry `Opened` — "would mask the recovery requirement" (bd-issue PRRO_GATE-ah8).
- **SEAM-D-1 | MED (new, CONFIRMED — composes with the just-merged NC-03).**
  My NC-03 fix (PR#148) branch (a) reconstructs the lost node_state row via
  `upsert_initial_tx(fn, Online, **Closed**, next_lnd)` + `current_shift_id=NULL`, reading ONLY
  `fiscal_documents` (max_lnd, last_ack) — it does **NOT** query the `shifts` table. But NC-03's
  domain (node_state lost, ledger survived) is the SAME DB file, so a surviving **OPEN `shifts`
  row** can coexist. Boot's crashed-shift recovery triggers only on `shift_state==Opened AND
  current_shift_id IS Some` (`boot_phase.rs:2910`); NC-03 set it to `Closed/NULL` → the surviving
  open shift is **masked from recovery** — exactly the hazard the node_state.rs contract names.
  MITIGATED (not silent): NC-03 also BLOCKs the node + CRITICAL audit, so no trading until an
  operator clears it. The gap is the **operator unblock procedure**: if they unblock without
  reconciling the shift, the open shift stays masked. FIX (small, follow-up to NC-03): branch (a)
  ledger-survived path should query `shifts`; if an open shift exists either preserve
  `shift_state=Opened`+`current_shift_id` so boot recovery sees it, OR (minimal) record the
  open-shift fact in the CRITICAL audit payload + RUNBOOK unblock step. This upgrades my own
  parked NC-03 residual from "noted" to a located, fixable item.
- §16.7 manual-recon routing: the drain reject of an OFFLINE_LOCAL_ACK backlog doc on
  OpenedLocalPendingDrain DOES route to RequiresManualReconciliation for the DPS-reject case —
  but NOT for the structural cases (M2-04 ChainSeedMismatch, SEAM-B-3 lastChk Mismatch), which
  hard-abort instead. See Synthesis.
- Channel-switch-forbidden-with-open-shift (#3): enforced at acquire (mode gating) + Z/shift

## Synthesis — the one coherent class

Three of the findings (M2-04 from the M2 review, **SEAM-B-3**, and the structural half of the
§16.7 routing) are the SAME CLASS: **the offline-drain path hard-aborts (`BootError::Internal`)
on structural/chain anomalies instead of routing them to §16.7 RequiresManualReconciliation**,
while the boot + convergence drivers already route gracefully (M1-02 TIP_SUPERSEDED, manual-recon
arms). The offline drain is the youngest of the three drivers and did not inherit the graceful
arms. **Recommended batch — "offline-drain robustness":**
1. SEAM-B-3: superseded exception in `classify_check_result` (uniform with dispatch_sent_via_probe).
2. M2-04: ChainSeedMismatch → manual-recon class (already in the M2-01 fix design as a separate item).
3. (after M2-01 lands) re-audit the drain StructuralDrift arm: which structural drifts are
   genuinely fatal vs operator-recoverable.

**SEAM-D-1** is separate (a node_state-reconstruction gap, follow-up to NC-03) and small.

**SEAM-C-1** is an A2.4 pre-flight checklist item (dormant inline path).

Nothing here blocks the M2-01 fix; SEAM-B-3 + M2-04 want to land in the same offline-drain batch.
