## 1. Root cause + fix

M2-01 turned offline-origin docs into a **strict predecessor chain** (each offline doc signs
`previous_hash = unsigned(prior issued doc)`; the seed advances at OfflineLocalAck). The
offline-drain SEQUENCING predated that and still **sibling-continued** past a failed doc
(halting only on `if shift_in_pending_drain`). Sending `lnd+1` whose predecessor was
rejected/held is unsafe (cascade-reject / broken wire-chain) — the GPT-critic FT.

**Fix:** the offline drain is now **strictly sequential** — it STOPS at the first non-ACK doc.
The cohort is entirely `fs_mode='OFFLINE'` (`list_drain_candidates_for_fn_ordered_by_lnd`
filters it), so this applies to the whole per-doc loop; online-origin docs converge via the
separate `online_convergence` tick (untouched).

## 2. Conformance per contract item + ruling B

### M2-N1 / M2-N2a — strict-sequential drain + escalation (`backlog_drain.rs`)
The `if shift_in_pending_drain`-only halt gate is **removed**; the per-doc loop is now a 5-way
match on the verdict (architect **ruling B** matrix):

| Verdict | Action |
|---|---|
| `Advanced` (ACK) | continue to `lnd+1` |
| `Failed{manual_recon:true}` (REJECTED / doc-manual) | **halt + escalate FN → RequiresManualReconciliation**, regardless of shift_state |
| `SupersededHeld` (no B1-v2) | **halt + escalate Manual** (reverses SEAM-B-3's continue) |
| `HoldFnDrain` (transient hold) | **halt this tick, NO Manual**, keep REC-1 tier budget |
| `Failed{manual_recon:false}` (ERROR_RETRYABLE / probe-required) | **halt this tick, NO Manual**, retries next tick |

Per ruling B: terminal / non-self-resolving → escalate (would wedge otherwise, M2-N2a);
transient → halt-this-tick + retry-next-tick (no wedge — the doc stays in the cohort —
so escalating to Manual on the first transient blip would be a false ЧП and would orphan
the REC-1 tier degradation, which exists precisely for a persistently-held predecessor).

### M2-N2a — `Opened → RequiresManualReconciliation` whitelist edge 15 (`shifts.rs`)
A plain `Opened` shift (online-opened, dropped offline mid-shift) had **no** `→Manual`
whitelist edge — only 6/14 (pending-drain). Added **edge 15** (per your direction: a normal
state-machine branch, NOT the `force_to_manual_reconciliation_with_audit` seam). `escalate_
drain_to_manual` reuses `apply_shift_transition` uniformly for Opened + pending-drain.
Updated: the §4.1 edge list + §4.4 reachability note, the 9×9 matrix test (14→15 Applied /
67→66 Forbidden), `tier_b` Manual-source set (4→5).

### M2-N2b — scan issued-set (`invariant_scan.rs`)
Added `REJECTED` + `REQUIRES_MANUAL_RECONCILIATION` to the offline-origin branch of the
MAC-walk issued-set. An offline-origin doc that reached OFFLINE_LOCAL_ACK already advanced
the seed (M2-01); a successor chained off it before the drain rejected/manual-escalated it.
Without this, the walk does not advance over the rejected predecessor → **false ChainBreak**
at the successor. Online-origin unchanged.

### M2-N4 — superseded requires matching tip id (uniform: `kvt2_confirm.rs` + `boot_phase.rs`)
Superseded ⟺ `doc.lnd < max_submitted_lnd` **AND** `actual_id` == `server_fiscal_no` of a
submitted doc with `lnd > doc.lnd`; else `StructuralDrift`. New repo fn
`fiscal_documents::submitted_above_lnd(fn, lnd) -> Vec<(lnd, sfn)>`.
- **Classifier stays PURE:** `classify_check_result` keeps its `superseded: bool` input
  (unchanged signature, 16 unit tests untouched). `evaluate_lastchk` computes the bool
  POST-DPS (where `actual_id` is known) from the caller-fetched newer-submitted sfn set;
  `confirm_drain_doc` fetches that set (replacing the lnd-only `max_submitted_lnd` read).
- **Boot M1-02 arm** uses the same query: superseded only if `actual_id` matches a newer
  submitted doc's sfn; else terminalise to Manual.
- A foreign / garbage tip (with a newer submitted doc present) → genuine structural drift,
  no longer masked as benign supersession.

## 4. Decisions / items flagged for your call

### A) Ruling B applied as you directed
Terminal/superseded → escalate; transient (HoldFnDrain / ERROR_RETRYABLE / probe-required) →
halt-this-tick + retry, REC-1 tiers preserved. The `HoldFnDrain` arm keeps its existing
record + Tier 1/2 trigger logic (now reached when a transient predecessor persists across
ticks — exactly the case the tiers exist for).

### B) SEAM-B-3 reversal (disclosed consequence)
A superseded predecessor now halts + escalates Manual (was sibling-continue). Consequence: a
known-DPS-fiscalised tip doc that sits BEHIND a superseded predecessor is left SENT (not
auto-converged) and the FN goes Manual. This is conservative-correct (chain integrity is
unverifiable while a predecessor's ACK status is unknown) and is exactly the M2-N1 contract
note ("SupersededHold … must ALSO stop the chain"). The SEAM-B-3 test was reversed accordingly.

### C) Real-inline N1 pin — **DELIVERED (architect ruling a, 2026-06-14)**
The N1 pin text said "3 offline SELLs **via the REAL inline path**".  Landed as
`kill_point_matrix.rs::m2_n1_three_real_offline_sells_strict_drain_halts_on_reject`:
node Offline + open offline session + 3 offline codes → **3 offline SELLs through the REAL
`inline::run` path** (distinct idempotency keys via the existing `seed_inbox_sell_keyed` —
the cross-harness fix), each landing at `OFFLINE_LOCAL_ACK` with `previous_hash =
unsigned(prior issued doc)` built REALLY by M2-01's seed-advance (NO hand-seeded prev).  Then
`set GoingOnline` (plain `Opened`) + drain with a stub that ACKs doc1, `Authorization(DocumentReject)`s
doc2, and provides nothing for doc3.  Asserts: doc1 → ACK, doc2 → REJECTED, **doc3 NEVER sent**
(`send_chk == 2`, doc3 stays `OFFLINE_LOCAL_ACK`), FN → `RequiresManualReconciliation` (edge 15,
plain Opened, NOT wedged), `invariant_scan::assert_clean` over the REAL chain incl. the REJECTED
offline-origin predecessor.  This closes the M2-02 class — the FT is now pinned against a
genuinely-reachable chain, not an aspirational hand-seed.  (The earlier `strict_sequential_
terminal_reject_...` raw-seed-with-real-chain pin remains as a focused drain-loop unit.)
