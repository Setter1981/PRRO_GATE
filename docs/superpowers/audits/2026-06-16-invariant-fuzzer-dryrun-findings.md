## P1 — REAL PRODUCTION GAP (PROVEN end-to-end, HIGH): boot post-sign-refusal resume does not abort the dangling doc — the boot-path twin of #192

**Class:** FALSE-NEGATIVE (fuzzer cannot reach it) **over a real production durability hole.** · **Lens:** C/E (Auditor 3 F2). · **Confidence:** PROVEN — upgraded from "HIGH/static read" to **dynamic end-to-end repro** (2026-06-17). A `#[tokio::test]` boots the full `App`, seeds the crash-recovery shape, runs the production boot driver `App::reconcile_pending_with → run_boot_reconciliation`, and observes the doc left stuck in `SIGNED`. See **VERIFICATION VERDICT** below. The terminal-vs-deferral semantics is no longer "open" — the live path already settled it (it aborts), so the boot asymmetry is the bug.

**The gap.** The #192 fix aborts a dangling `{PREPARED,SIGNED}` doc → `Aborted` **only inside the live `inline::run` path** (`inline.rs:254-311` `terminalise_inbox`; the live `PostSignRoute::Refused` arm at `inline.rs:615-617` and `OfflineAckOutcome::Refused` arm at `inline.rs:631-636` both terminalise → `Aborted`). The **boot-resume path was not given the same fix — and the defect spans BOTH boot resume entry points** (blast radius wider than first recorded; verified by direct read):
- **SIGNED-resume** (`dispatch_pending_doc`, `DocState::Signed` arm — a doc that crashed *after* the SIGN commit):
  - `boot_phase.rs:3745` — `Ok(PostSignRoute::Offline { outcome: OfflineAckOutcome::Refused(_) })` → **only** `histogram.write_path_dispatch_refused += 1`. No transition, no abort.
  - `boot_phase.rs:3750` — `Ok(PostSignRoute::Refused(_))` → **only** the histogram bump.
- **PREPARED-resume** (`dispatch_prepared_via_chain` — a doc that crashed in `PREPARED`; boot drives `stage_sign::run` PREPARED→SIGNED, then dispatches post-sign):
  - `boot_phase.rs:3514` — `Ok(PostSignRoute::Offline { outcome: OfflineAckOutcome::Refused(_) })` → **only** the histogram bump.
  - `boot_phase.rs:3522` — `Ok(PostSignRoute::Refused(_))` → **only** the histogram bump.

  In every one of the four arms the doc is left resting in `SIGNED`. A fix that patches only the `DocState::Signed` arm would leave `PREPARED → SIGNED → refused` orphans on the chain path — the fix contract must cover both entry points.

**Why it is reachable (verified):**
- A SIGNED doc *does* enter the boot pending-dispatch set: `list_pending_for_fn` (`fiscal_documents.rs:493`) selects `state IN ('PREPARED','SIGNED','ENCRYPTED','SENDING','SENT','KVT1','KVT2','ERROR_RETRYABLE')`, and boot has a live `DocState::Signed` dispatch arm.
- A SIGNED doc rests at boot only after a crash between the SIGN commit and dispatch — a real crash window.
- On reboot, `dispatch_post_sign` runs against the *current* node mode. A **terminal** refusal is reachable: `OfflineAckOutcome::Refused(CodePoolExhausted)` is the **exact #192 trigger** (offline code pool exhausted) and will not self-resolve. The live path aborts it; the boot path leaves it in `SIGNED`.

**Consequence.** A stuck non-terminal `SIGNED` row resting in `fiscal_documents` = a ledger-only-pin violation (the ledger is issued-receipts + transport-class `Sending`/`ErrorRetryable` only). It is the precise invariant #192 closed, re-opened on the boot branch. Compounding (X1 below): the `StuckNonTerminalDoc` scan that *would* catch it is **test-only** — never run in production — so nothing surfaces it at runtime.

**Severity nuance (do not oversell).** Leaving a SIGNED doc resting at boot is *defensible deferral* for a **transient-mode** refusal (`GoingOnline`/`Blocked`/`StopMode`/`CryptoDegraded` that later clears → the doc dispatches on a subsequent boot). It is a genuine **orphan** only for a **terminal** refusal — primarily `CodePoolExhausted`, which will not clear while the FN stays offline. The fix must distinguish the two, exactly as the live path's #192 design already does — and the asymmetry is the bug: a crash-then-reboot must not change a doc's terminal outcome (Frozen Invariant #8). On reboot in the *terminal* subset the live path would have produced `Aborted`; boot produces a resting `SIGNED` that the next online boot will **resurrect and send** → a refused operation becomes an issued receipt (the exact #192 blast radius).

**Why the fuzzer cannot reach it.** The alphabet has no `Crash(Sign)` stage (only `Crash(Send|Kvt1)` — see O4) and no op that sets a refusing node mode at boot. So the fuzzer can never seed "a SIGNED doc + a refusing mode at reboot." This is a fixture/alphabet blind spot sitting directly over the #192 fix's incomplete edge.

**VERIFICATION VERDICT (2026-06-17) — REPRODUCED, terminal subset reachable.**
An ignored `#[tokio::test]` repro (`p1_boot_resume_signed_refused_repro.rs`, run under `--features test-support --run-ignored`) booted the full `App`, seeded a committed `SIGNED` SELL doc on an **OFFLINE** node with an **empty `offline_codes` pool** (→ `acquire_code_tx` returns `Ok(None)` → `OfflineAckOutcome::Refused(CodePoolExhausted)`, `offline_sessions.rs:408`), and ran the production driver `App::reconcile_pending_with`. Observed runtime evidence:
- `doc state after boot = SIGNED` (the live path would have `Aborted` it).
- boot summary counters: `write_path_dispatch_refused: 1`, `branch_d_offline_refusal: 0`, `signed_deferred: 0`, `signed_dispatched: 0`, `offline_local_ack_emitted: 0` — i.e. the doc **reached the per-doc dispatcher and traversed exactly the `boot_phase.rs:3745` arm** (not short-circuited, not deferred, not advanced).
- `invariant_scan::scan` returns `StuckNonTerminalDoc { state: "SIGNED" }` for the doc.

This is the precise terminal subset the verification was asked to confirm: a real SIGNED-survivor crash + reboot into offline-without-codes leaves a durable ledger-only-pin violation. **Confidence is now dynamic, not inferred.**

*Distinction worth recording (the fallback case is NOT the same arm):* the companion `BLOCKED`-mode variant also leaves the doc `SIGNED`, but its counters were `branch_f_blocked: 1`, `write_path_dispatch_refused: 0` — it is short-circuited by the node-wide **`branch_f`** mode skip and **never reaches the `3745`/`3750` dispatcher arms**. That variant therefore demonstrates a *separate* concern — `invariant_scan` over-flagging a **transient-mode** resting doc (a scan-gate issue in the O-series family), not the P1 abort-asymmetry. Do not cite the BLOCKED case as evidence of the dispatcher-Refused arm; the OFFLINE+exhausted case is the load-bearing proof.

**Recommended action (triage contract, NOT a unilateral fix — hot-zone boot reconciliation):**
1. Decide the semantics: at boot, a `PostSignRoute::Refused` / `OfflineAckOutcome::Refused` that is **terminal** (`CodePoolExhausted`, and any other non-clearing reason) must abort the dangling SIGNED doc → `Aborted` in the same envelope, reusing the live path's `terminalise_inbox` abort; a **transient-mode** refusal stays deferred (current behaviour, correct). **Apply symmetrically to all four arms** (SIGNED-resume `3745`/`3750` + PREPARED-resume `3514`/`3522`).
2. RED pin: the implementer lands the verified offline-exhausted repro (source preserved in the appendix below) as a kept regression test — RED against current code, GREEN once the symmetric abort lands. Per role split this is the implementer's test-first starting point.
3. Close the fuzzer blind spot in the same tranche: add a `Crash(Sign)` stage + a mode-forcing op so `Crash(Sign) → boot-in-refusing-mode` is expressible; then the harness `StuckNonTerminalDoc` scan bites it as a regression gate.
4. Separately consider X1 (wire a cheap `StuckNonTerminalDoc` subset into `run_boot_reconciliation`'s tail so this class is a *runtime* guard, not only a test oracle). Note: a runtime scan would also flag the *transient* BLOCKED case above, so it must be mode-gated (the same SETTLED scan-gate the O-series flags).

## Oracle false-negatives — the fuzzer would pass while a real bug exists

### O1 (HIGH) — online-origin docs stuck non-terminal (`SENT`/`KVT1`/`ERROR_RETRYABLE`) are blessed as clean; the convergence seam is never driven
**Lens A (Auditor 1 F1).** `StuckNonTerminalDoc` flags only `{PREPARED,SIGNED,ENCRYPTED}` (`invariant_scan.rs:60-63`); `SENT`/`KVT1`/`ERROR_RETRYABLE` are excluded as "legitimately resting" — an exclusion written for the offline cohort but applied to online-origin docs too. The seam that would resolve a stuck online doc, `online_convergence::run_tick_for_fn`, is **never called by the interpreter** (only boot-recon and offline `drain` are). The offline cohort gets a real drain-tick at settle; online docs get nothing — an asymmetry. A `[Crash(Send)]` settles to `ERROR_RETRYABLE` and `assert_clean` passes (the harness's own A2 test asserts this). The harness comment at `invariant_fuzzer.rs:1110` claims "drain/convergence resolves it" — false for online docs. **Fix:** drive `online_convergence::run_tick_for_fn` (Ack-loaded) in `settle_and_scan` symmetric with the offline drain-tick, so a doc that *should* converge but doesn't becomes a liveness failure.

### O2 (HIGH) — `Crash`/`Reboot` faults get NO bounded postcond and NO differential — blind `resync_from_db`
**Lens B+C (Auditor 2 F2, Auditor 3 F1 — convergent).** The MH bounded postconds run only for `matches!(op, Drain|RepeatDrain|GoOnline|GoOnlineWithoutBacklog)` (`invariant_fuzzer.rs:939-942`); a `Crash(_)`/`Reboot` falls straight to `model.resync_from_db` (L984) with zero independent check, and its differential is `Ok(())` unconditionally (`oracle.rs:85`). A `Crash(Send)` on an **Offline** node completes a *real* offline sell (mints `OFFLINE_LOCAL_ACK`, consumes a code) that is never differential- or bounded-checked. Crash-mid-offline-sell is precisely the dominant "recovery-under-fault" bug class, and the oracle is weakest there. **Fix:** when a "crash" returns a completed `Doc`, route it through the same differential the `PredictableMutating` arm uses (the model can predict an offline sell deterministically); and extend the bounded postconds to Crash/Reboot.

### O3 (HIGH) — the chain oracle is *referential-only*: no content-hash recompute, so a corrupt-but-self-consistent hash passes clean
**Lens B (Auditor 2 F1).** The model assigns a synthetic per-lnd placeholder `synth_unsigned_hash(lnd)` and the differential is explicitly structural ("we NEVER compare model bytes to real bytes", `oracle.rs:145-155`). The L2 chain walk (`invariant_scan.rs:223-282`) compares `previous_hash` against the **stored** `unsigned_xml_sha256` of the prior doc — it never recomputes `sha256(canonical_xml)`. So a seam that writes a wrong-but-consistently-threaded hash (hashes placeholder XML, the previous body, or a constant) passes L1 + ChainBreak + ChainSeedMismatch simultaneously. "Chain linkage" is *referential*, not cryptographic — weaker than the brief implies (corrected in the brief, see below). **Fix:** recompute the content hash for the docs the fuzzer mints (wire the seam's canonicaliser, don't reimplement), at least behind the directed pins.

### O4 (HIGH, also a brief-honesty fix) — only 2 of 8 crash stages are ever generated
**Lens C (Auditor 3 F3).** `Stage` enumerates 8 points, the brief presents the crash model as covering them, but `strategy.rs:41` emits **only** `Crash(Send)` and `Crash(Kvt1)`; every other `Crash(stage)` is `unimplemented!()` in `interp.rs:446-449`. The unreachable stages include `Finalize` (the ACK-commit↔inbox/audit-write window) and `OfflineAck` (the local-commit↔drain-threshold boundary — **the #192 birth site**). So the fuzzer can never crash *inside* the very envelope where the #192 orphan is born; it only catches steady-state residue. **Fix:** implement at least `Crash(Finalize)` + `Crash(OfflineAck)`, and (done here) correct the brief to state plainly only `{Send,Kvt1}` are injected.

### O5 (MEDIUM) — terminal `ArtifactNoResend` skips the *whole* scan, not just the excused transient
**Lens A+C (Auditor 1 F3, Auditor 3 F7 — convergent).** When the terminal verdict is `ArtifactNoResend` (GoingOnline + no active session / empty cohort / ineligible shift), `settle_and_scan` asserts only `send_calls == sends_before` and runs neither `assert_clean` nor `check_mirrors` (`invariant_fuzzer.rs:891-905`). The §15 justification is one legitimate transient (a deferred online-origin `SENDING` would false-flag `StuckSending`) — but the suppression is *total*: any co-resident `ChainBreak`/`DuplicateLnd`/Mirror-2 desync is also skipped, and because it is the terminal, there is no later boundary to re-catch it. **Fix:** in that branch run `scan()` but filter out only the known transient doc by `document_id`, asserting the remaining violation set is empty (the per-violation filter the §15 contract deferred).

## Model drift / vacuity — the differential tests fiction at these points

- **D1 (MED-HIGH) — `next_lnd` adopted from DB in `resync_from_db`** (`model.rs:443-444`): after a fault the model predicts the next lnd by reading back the value the crashed system just wrote, so `doc.lnd != m.lnd` compares the system to a number derived from itself — vacuous. Only `DuplicateLnd` (a collision) is independently caught; an off-by-one/gap is not. *Lens B (Auditor 2 F3).* **Fix:** derive `next_lnd = max(adopted lnds)+1` and assert the DB value equals it.
- **D2 (MED) — per-op `resync_preconditions_from_db` adopts mode/shift/session** (`invariant_fuzzer.rs:1157-1159`, `model.rs:474-490`): on the hot path of *every* non-fault op the model overwrites mode/shift/session from the DB, so a wrong mode/shift transition by a write-path op is invisible to the differential; only the internal-consistency mirror-scan can catch it, and a coherent-but-wrong transition (both columns agree on the wrong state) passes. *Lens C (Auditor 3 F5).* **Fix:** predict + assert the mode/shift transition for the ops the model already understands (go_online, drain-reject→RMR) before resyncing.
- **D3 (MED) — issued-set shares the production SSOT const** `OFFLINE_ISSUED_STATES` (`model.rs:124` == `invariant_scan.rs:268`): model, scan, and seam agree "by construction"; a drift in the const cannot be disagreed with. *Lens B (Auditor 2 F4).* **Fix:** in the *model* hard-code the literal independently with a `debug_assert` it equals the const (the one place "fork + assert-equal" beats "share").
- **D4 (MED) — `BadHashPrev` online-sell deferred to `Fault` (blessed) rather than derived** (`model.rs:230-232`): the recovered terminal is *adopted*, not asserted, and the send/no-resend bound doesn't apply to this online-sell-fault — so a spurious resend or wrong terminal here is caught only if a paired `Reboot` follows. The brief lists this as a "derivation"; it is a *deferral*, which is weaker. *Lens B (Auditor 2 F5).* **Fix:** predict the single-shot-stub terminal, or at least apply the no-resend bound to this op.
- **D5 (MED) — exotic-drain `Fault` deferral masks a wrong terminal inside the `2×cohort+1` send bound** (`model.rs:408-410`): a deferred drain could re-drive docs in the wrong order / wrong subset / wrong state and still satisfy the coarse bounded postconds; the exact terminal ledger is never asserted. Compounds the brief's known-weakness #3 (shallow multi-doc drain). *Lens C (Auditor 3 F6).* **Fix:** promote the *deterministic* exotic scripts (Superseded→all ERROR_RETRYABLE; NotFound-hold→SENT) to predicted `Mutated`, shrinking the Fault bucket to the genuinely-nondeterministic MAC-recovery case.

## Coverage / scan-vocabulary gaps — "clean" ≠ legally clean

- **C1 (MED, legal) — offline-cap / lnd-monotonicity / cross-FN are unmodeled end-to-end.** *Lens A+C (Auditor 1 F5, Auditor 3 F8 — convergent.)* The scan has **no variant** for: **offline time/code-limit breach (Frozen Invariant #5)** — and the fuzzer calls `backlog_drain::drain` *directly*, bypassing the caller-side time-window eligibility gate; **lnd monotonicity/no-gap (INV-02)** — only `DuplicateLnd` exists; **cross-FN bleed** — all fixtures use one FN, so the lease-model attribution risk is structurally unreachable. **Fix (highest-value):** add an `OfflineCapExceeded` variant + a fixture seeding a real `max_offline_codes` (the offline cap is a hard legal limit, presently unmodeled); add a `LndGap`/`NextLndDrift` variant.
- **C2 (MED, latent) — `(OfflineLocalAck, Cancelled)` corruption has no `Violation` variant** and no auto-invoker today (operator/force-seam only). *Lens A (Auditor 1 F2).* A doc that reached `OfflineLocalAck` advanced the seed + consumed a code; if later `Cancelled` (an allowed transition, `fiscal_documents.rs:231`) it leaves `OFFLINE_ISSUED_STATES` — but no variant names "a backed code / advanced seed on a non-issued terminal." Live the moment Cancel is wired (Phase-2 RETURN). *Verified honest:* the offline-refusal `Aborted` doc carries `offline_fiscal_no = NULL` (pool untouched on refusal), so it is correctly *not* a corruption today. **Fix:** add `Cancelled` to `OFFLINE_ISSUED_STATES` (same M2-N2b seed-advance argument as `REJECTED`), or a `BackedCodeOnNonIssuedTerminal` variant.
- **C3 (MED, bounded) — `ExpectedNoIssuanceRow` cross-checks against `model.docs`** (the model's own prediction) via `check_ledger_delta` (`invariant_fuzzer.rs:1055-1073`): if the model's mint-prediction and the real seam are *jointly* wrong, the delta matches and it passes. The seed/code guards (real-vs-real) block the obvious cases, so it's bounded. *Lens A (Auditor 1 F4).* **Fix:** assert new-row count ≤ 1 and new state ∈ {Rejected, Aborted} directly from the DB, independent of `model.docs`.

## Process / operational

- **X1 (MED-HIGH) — `assert_clean` is test-only** (`invariant_scan.rs:33` `#![cfg(any(test, feature="test-support"))]`, zero `src/` callers). *Lens C (Auditor 3 F4).* The brief's "zero prod callers gate it off" is confirmed — but the stronger truth is the `StuckNonTerminalDoc` invariant (the #192 enforcement) is **never enforced at runtime**; only CI tests exercise it. This raises the stakes on every coverage gap above: a hole the fuzzer misses ships unmonitored. **Fix:** wire a cheap subset (`StuckNonTerminalDoc` + `StuckSending`) into `run_boot_reconciliation`'s tail and/or a health tick.
- **X2 (LOW, latent) — `LIMIT 1` without `ORDER BY`** on the active-session lookup (`model.rs:484-489`, `oracle.rs:286-292`). *Lens B (Auditor 2 F7).* Latent under the single-session fixture; becomes a nondeterministic repro + Mirror-2 false-negative the day a second session enters the alphabet (Phase-2). **Fix:** add `ORDER BY` + a single-active-session guard assert (fails loud when violated).
- **X3 (MED) — no seed-corpus persistence** (`ProptestConfig { cases: 256 }`, no `failure_persistence`). *Lens C (Auditor 3 F10).* Rated above "Tier-1 nicety": the teeth artifacts (TEETH_TEST.md, #192 mirror) are the *only* durable regression gates; every other fixed bug has no pinned seed, so a re-regression must be re-discovered by chance at N=256. Directly undercuts the "CI-grade" claim. **Fix:** enable proptest file-based regression persistence committed to the repo + add each shrunk find as a directed `#[test]` (generalize the AUD-K8-1/#192 pattern).

## Confirmed SOUND (recorded so the external auditor does not re-chase)

- **#192 resurrection-guard breadth** — all three boot-feeding pending queries exclude `Aborted` by enumeration: `list_pending_for_fn` (`:493`), `newest_pending_submittable` (`:830`), `list_drain_candidates_for_fn_ordered_by_lnd` (`:1005`); the `dispatch_pending_doc` Aborted arm is a `bail!` contract-check, not the guard. **No second query re-opens resurrection.** *(Modulo P1, which is a distinct boot-SIGNED-resume hole, not a resurrection of an Aborted doc.)*
- **#192 transition completeness within `inline::run`** — every outgoing edge of `PREPARED`/`SIGNED` either advances the ladder or lands a terminal; no edge re-creates a resting non-terminal orphan *on the live path*.
- **AUD-K8-1 teeth mode-independence** — the RMR no-resend check counts wire calls (not a scan), genuinely survives the SETTLED gate. **Load-bearing.**
- **`code_consumed` differential** — independent across non-fault ops (`resync_preconditions_from_db` does *not* touch the code counter); a genuine derivation, not vacuous. *(Re-introduces vacuity only across full faults, covered by the drain bounded-postcond — gap is the Crash/Reboot subset, = O2.)*
- **Determinism** — the `std::mem::forget` temp-DB leak, `Utc::now()` reads (audit timestamps, not control-flow), and ordered collections do **not** break replay; the single-threaded harness has no drain concurrency. The real reproducibility risk is X3 (non-persistence), not nondeterminism.
- **Doc hazard (not a bug):** the model's comments attribute the GoingOnline no-row outcome to a "post-sign dispatcher" refusal, but the real seam refuses **pre-sign** at `stage_acquire.rs` Step 3a (before the PREPARED insert). The *prediction* (NoMutation/no row) is correct; the comment's mental model is wrong — a maintenance hazard if someone "fixes" the model to match the comment.
