> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve the three open risks left by the M2 pre-plan ADR (`docs/superpowers/specs/2026-05-04-m2-pre-plan-adr.md`, approved 2026-05-04 at HEAD `0d6b4c5`) so the M2-W1+ implementation plan can be written against verified inputs instead of guesses.

**Architecture:** Research-only.  Each task produces a frozen findings document under `docs/superpowers/specs/`.  Production source code is **not** modified by this plan. **Tech Stack:** No new tech.  Existing repository contents (Python sidecar, `rust/prro_crypto`, `rust/prro_sidecar`, current `scripts/mock_dps_server.py` + `scripts/mock_dps.proto`, current `src/prro_gateway/transports/proto/fiscal_server.proto`, M1 schema) plus targeted protocol-level reading (RFC 4210 for CMP, gRPC/HTTP/2 spec where needed).

**Hard scope rules:**
- This plan has **exactly 3 tasks**.  No Task 4 / W1+ implementation.  Adding tasks here is a scope violation.
- Each task ends with a findings doc.  No production code, no `rust/prro/src/**` edits.  Allowed code-shaped artefacts are inert reproduction snippets inside the findings doc and ADR fix-commits if findings demand them.
- Each task is sized in **days**, not minutes.  These are real research questions; the plan must not pretend they are mechanical.
- Each task explicitly names its findings-doc path so the W1+ implementation plan (written **after** this one) can cite them.
- W1+ implementation plan is **blocked until all three findings docs land**.  The wrap-up section pins this.

## ADR revision procedure (applies to all three tasks)

When a task's findings contradict an ADR section:

1. Author opens a docs fix-commit on `rust-gateway` editing
   `docs/superpowers/specs/2026-05-04-m2-pre-plan-adr.md` only.
   Commit message format:
   `docs(spec/m2): ADR-M2-N revision after W0-K findings`.
2. The ADR section's "Decision" is rewritten to the new shape.  The
   "Alternatives rejected" entry that was the new shape's previous
   home is moved to "Decision".  Do NOT silently delete history —
   add a one-line note `(was: <previous decision>; revised <date>
   per <findings-doc>)`.
3. The "Open risk" entry that motivated the W0 task is replaced with
   a `Resolved <date> — see <findings-doc>` line.
4. Review status is downgraded from `approved` to `re-review pending`
   until the reviewer signs off the revision.  Do NOT skip this step.
5. If a finding does **not** contradict the ADR, no revision is
   needed — just the findings doc and a note in the doc that it
   confirms the ADR.

**Deferral path:** if a question cannot be answered within the task's
day budget without external input (e.g. waiting for prod-traffic
samples from operations), the findings doc must explicitly say so,
list the assumption that closes the gap, and mark the assumption as
"deferred to W1 implementation, ADR not revised".  This is a
documented escape hatch, not a silent skip.

## When all three tasks are done

- Three findings docs live under `docs/superpowers/specs/`.
- ADR-M2-1, -2, -4 (and possibly -5) have either confirmed-unchanged
  notes or revised "Decision" sections with `Resolved <date>` open-risk
  entries.
- The reviewer re-reads the ADR; if `re-review pending` was set during
  any revision, it is bumped back to `approved` (or the cycle repeats).
- `superpowers-extended-cc:writing-plans` is invoked on the M2 W1+
  scope, which can finally name concrete tasks because:
  - the DPS mock is being written against a verified `.proto` (or a
    verified SOAP/REST contract);
  - `cert_refresher` is being sized against a known CMP message set
    and a chosen test-CA strategy;
  - `prro::crypto` is being implemented against a known
    `prro_crypto` API + a frozen `CryptoProvider` trait shape.

Until those three things are true, the W1+ implementation plan does
not get written.  This is the design promise of M2-W0.
