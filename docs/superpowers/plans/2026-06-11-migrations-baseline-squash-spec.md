# Squash миграций в baseline — спека (одноразово, до-пилотное окно)

**Дата:** 2026-06-11
**Архитектор:** Fable 5 | **Имплементатор:** Opus 4.8 | **Статус:** SPEC LOCKED
**Когда:** после мерджа PR-B (boot tip-guard), до M4-ревью и A2.2.

## 1. Цель и скоуп

`rust/prro/migrations/` (24 файла, 156K археологии: переименования состояний,
W-инкременты) → **один `001_baseline.sql`**. `migrations_secure/` (2 файла) —
**НЕ трогать** (археологии нет, выгоды ноль).

## 2. Метод генерации (ЗАЛОЧЕН — исключает ручную транскрипцию)

SQLite хранит литеральный текст DDL в `sqlite_master`, поэтому baseline НЕ
пишется руками — он **генерируется из полностью смигрированной БД**:

1. Свежая БД → прогнать текущую цепочку 001-024 (обычный `open_pool` или
   `sqlx migrate run`).
2. `sqlite3 file.db .schema` → это и есть тело baseline, С ИСКЛЮЧЕНИЯМИ:
   - выкинуть `_sqlx_migrations` (sqlx создаёт её сам);
   - выкинуть внутренние объекты `sqlite_*` (`sqlite_sequence`,
     `sqlite_autoindex_*` — их нельзя создать явно).
3. Поверх — **курируемые комменты** из старых миграций: пройти 001-024, перенести
   ещё-истинные load-bearing блоки (W-/INV-/ADR-ссылки, обоснования индексов и
   CAS-инвариантов) как SQL-комменты к соответствующим объектам. Комменты не
   попадают в `sqlite_master` → на гейт эквивалентности не влияют.
4. Удалить 001-024, положить `001_baseline.sql`. Следующая миграция проекта — 002.

## 3. Гейт эквивалентности (обязателен, вывод — в PR-body)

Скрипт `rust/prro/scripts/verify_baseline.sh` (коммитится для воспроизводимости):
1. БД-A: применить СТАРУЮ цепочку (файлы достать из git: `git show <ref>` /
   worktree на пред-squash коммит).
2. БД-B: применить новый baseline.
3. Дамп обеих: `SELECT type, name, tbl_name, sql FROM sqlite_master
   WHERE name NOT LIKE 'sqlite_%' AND name != '_sqlx_migrations'
   ORDER BY type, name;`
4. **`diff` обязан быть ПУСТЫМ.** Не-пустой diff = СТОП, эскалация (никаких
   «нормализаций» поверх — метод §2 гарантирует пустоту by construction).
5. Полный `cargo test -p prro --features test-support` (1371+, каждый тест
   мигрирует in-memory БД baseline'ом — это и есть функциональный гейт)
   + fmt + clippy (не должны затронуться).

## 4. Fence

- **Ни одного схемного изменения контрабандой.** Baseline байт-в-байт повторяет
  итог старой цепочки (метод §2). Замеченные warts схемы → секция «Findings for
  architect review» в PR, НЕ чинить.
- Кода (src/**) не трогать вообще. `db/mod.rs` менять не нужно
  (`sqlx::migrate!("./migrations")` подхватит baseline как есть).
- Untracked-файлы оператора, secure-миграции, LEGAL_INVARIANTS, CLAUDE.md,
  workflows — не трогать.

## 5. Side-effect: существующие дев-БД

После squash любая существующая БД отвергается checksum'ом sqlx. Для одноразового
rebaseline дев-БД с реальной ДПС-историей — секция в PR-body «Dev DB rebaseline»:
точная процедура (очистить `_sqlx_migrations`, вставить строку baseline с
checksum'ом, скопированным из свежесмигрированной БД: `SELECT * FROM
_sqlx_migrations` там же). Исполняет оператор/архитектор локально; Opus только
документирует. Прочие дев/тест-БД просто пересоздаются.

## 6. Процедура

Ветка `chore/migrations-baseline` от свежего origin/main (git fetch!). Один
коммит-замена + скрипт. PR-body: вывод гейта (пустой diff + счёт сьюта), список
перенесённых коммент-блоков (file → секция baseline), Findings. НЕ мерджить —
ревью архитектора (перезапуск гейта).
